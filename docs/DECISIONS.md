- 결정: 입력은 마우스/터치. 필기 없음. 편집 범위(이동·삭제·페이지 관리·텍스트 등)는 인터뷰 Q7에서 확정.

## D-004 · 2026-10-24 · 브러시 성격 = 단계적(c)
- 결정: 1차는 필기 위주. 브러시 모델/임포터는 드로잉(스탬프/텍스처)까지 담는 구조로 설계. 엔진 확장은 후속.
- 이유: 외부 브러시 임포트가 차별점이고 Procreate 브러시는 대부분 스탬프·그레인 기반 → 모델을 좁게 잡으면 후속에서 포맷 재설계 필요.
- 미결: 1차에 최소 스탬프 렌더를 넣을지 → PLAN 단계.

## D-005 · 2026-10-24 · 동기화 = 구글 계정 로그인 + Google Drive (스펙 확장)
- 상황: 킥오프 인터뷰 가정은 "서버 없는 파일 동기화 폴더(OneDrive 등)"였으나, 사용자가 "굿노트 느낌, Android 노트를 노트북에서 바로 열기, 구글 계정 로그인"을 요구.
- 선택지: (1) Drive 앱 전용 숨김 폴더(appDataFolder) (2) Drive 내 보이는 폴더(`drive.file`) (3) 자체 서버 — 서버는 범위 밖으로 제외.
- 결정(잠정): Google Drive API 기반. 자체 서버 없음. 범위 (1)/(2)는 리서치에서 확정.
- 가정: 한 시점 한 기기 편집 / 충돌은 마지막 쓰기 + 충돌 사본 / 오프라인 우선 / 저장은 단일 직렬 큐(이전 앱 데이터 손실 교훈).
- 리스크(자료 부족, 리서치 대상): Windows용 Google 로그인(데스크톱 OAuth 루프백+PKCE) 지원 방식, Google Cloud 프로젝트 등록 및 OAuth 동의 화면 상태에 따른 토큰 만료 정책, 사이드로드 APK 서명 SHA-1 등록. **클라우드에서는 OAuth 클라이언트를 만들 수 없음 → LOCAL_TODO.**
- 영향: 의존성(Google 인증/Drive 라이브러리)은 PLAN의 승인 목록에 올림. 스택 판정 축에 "양 플랫폼 Google OAuth+Drive 구현 난이도" 추가.
