# 기능 비교표 — 굿노트 · 스타노트 · 삼성노트 · Notes+ vs Platen 1차

> 작성 2026-10-24 · Platen 리서처 · 입력 = `rea-goodnotes.md`(GN) · `rea-starnote.md`(SN) · `rea-samsung-notes.md`(SS) · `rea-notesplus.md`(NP) · `BRIEF.md`(BRIEF). **네 REA 문서와 BRIEF에 적힌 사실만** 썼고, 문서에 없는 칸은 "자료 부족"이다. 웹 검색·실측 없음.
>
> **셀 표기**: 짧은 관찰 + 근거 섹션 `(GN §2.3)` 식. 등급은 원문 표기를 그대로 옮김 — **공식**(스토어·도움말) / **1차**(파일·소스·사용자 직접 관찰) / **2차**(리뷰·위키·3자 분석) / **2차·3자 포맷 분석**(사용자 소유 파일의 바이트 분석 공개 스펙) / **추정** / **(스니펫)** = 검색 결과 발췌만 읽음 / **실측** = 이전 프로젝트 iwhg 실측(BRIEF 인정).
>
> **정리 완료(D-020 ③, 2026-10-24)**: SN·SS 문서의 디컴파일 유래 항목(§6 색인의 "메모 명시"·"동류", 그리고 APK 덤프 유래 "경계")은 두 REA 문서에서 삭제했고, 본 표에서 그 항목을 인용하던 셀은 **"자료 부족(디컴파일 유래 삭제)"** 로 바꿨다. 사용자 소유 파일의 바이트 분석(NOT4LONG01 format-spec, twangodev file-format)만 "2차·3자 포맷 분석"으로 유지. §6 색인은 처리 기록으로 보존하며 각 REA 문서 끝 "정리 기록"에 항목별 판단이 있다. † 표시는 모두 해소됨.
>
> **Platen 열의 표기**: "**1차**" = BRIEF 확정 / "**후속**" = BRIEF가 후속으로 못박음 / "**[가정]**" = BRIEF의 가역적 빈칸 / "**미명시 → 제안**" = BRIEF에 없어 REA 근거로 제안(승인 대상).

## 5. '가져올 원리'와 '버릴 것' 통합 목록

중복 통합 기준: 같은 메커니즘을 가리키면 한 항목으로 묶고 출처를 병기.

### 5-1. 가져올 원리 (통합 17개)

1. **활성 도구 재탭 = 세부 설정**, 글자 없는 아이콘 툴바와 일관. 굵기 3슬롯·색 3→12슬롯 상한. — GN 원리 1 · SN 원리 5
2. **Undo/Redo = 2/3손가락 "더블"탭을 매핑 테이블 기본 행으로**(단일 탭은 팜 충돌), 사용자 변경 허용. S펜 버튼 길게 누르기도 같은 테이블에. — GN 원리 2 · SN 원리 5
